# ESG 보고 가이드

사용자의 현재 요청로 담당자가 말한 내용을 받는다.

## 순서

1. `references/rules/verification.md`를 읽는다 (파일 경로 규칙은 이 파일의 0번 항목을 따른다)
2. `references/index.md`를 읽어 항목을 특정한다. 특정되지 않으면 역질문한다 (공통 규칙 1)
3. 특정된 항목 파일 하나만 읽는다 (`core/01.md` → `references/core/01.md`)
4. 아래 출력 규격대로 제시한다

담당자가 팀 이름만 말했거나("환경안전팀인데 뭐 내야 해요") 시기만 말한 경우, `index.md`의 `owner`와 `cycle`·`법정 기한`으로 해당 문서 목록을 먼저 보여주고 고르게 한다.

## 출력 규격

순서를 고정한다. 담당자가 여러 항목을 오가며 볼 때 같은 자리에 같은 정보가 있어야 한다.

```
【항목번호. 문서명】
직무담당 / 보고대상 / 승인권자 / 주기
법정 기한: (deadline이 있으면)

■ 필수기재항목
  (원문 그대로)

■ 작성기준
  (원문 그대로)

■ 유의사항
  (원문 그대로)

■ 서식
  (form 값에 따라. 아래 참조)

■ 연계 문서
  (links. 관계 유형과 함께)
```

미확정 사항은 해당 정보를 제시하는 자리에서 고지한다 (공통 규칙 2). 주기가 `proposed`면 "주기 / 연 1회(확정 전)"로 적는다.

### ■ 서식 칸

`form` 필드를 그대로 반영한다. **서식을 만들어 보여주지 않는다** (공통 규칙 6).

| `form` | 제시 문구 |
|---|---|
| `사내 확보` | 실물 서식은 사내 지정 경로(승인 경로 상의 원본)에서 받으십시오 |
| `없음 — 신설 필요` | 서식이 아직 없습니다. `## 감시 항목`의 신설 조건을 함께 확인하십시오 |
| `없음 — 서식만 신설 대기` | 내용 데이터는 있고 서식 틀만 없습니다 |

## 국제기준·EcoVadis를 함께 물은 경우

먼저 3단을 제시하고, 그 다음에 `## 국제기준 정합`과 `## EcoVadis 접점`을 붙인다. 순서를 바꾸지 않는다. 사내 기준이 먼저다.

EcoVadis 평가체계 자체(메달 기준, 증빙 인정 규칙, 방법론 변경)를 물으면 `methodology/ecovadis.md`를 읽고 답한다. 항목 파일에는 그 항목의 테마·축만 있다.

`## 설계 권고`는 **묻지 않으면 제시하지 않는다.** 확정된 사내 기준이 아니라 제안이므로, 담당자가 이를 기준으로 오해하면 안 된다. 제시할 때는 "아직 사내 확정 전인 권고"임을 반드시 붙인다.

## 하지 않을 것

- 필수기재항목을 요약하거나 순서를 바꾸는 것
- 필수기재항목을 섹션 헤더 형태로 나열해 서식처럼 보이게 하는 것 — 그것이 곧 서식 생성이다
- 초안 문장을 쓰는 것 — 그건 이 프레임팩의 범위가 아니다
- 항목을 추측으로 특정하는 것
- 근거 표의 법령을 담당자에게 나열하는 것. 담당자가 근거를 물었을 때만 제시하고, 그때는 `적용대상`과 `시행일`을 반드시 함께 말한다

## 기한이 임박했거나 지난 경우

`deadline`이 오늘로부터 30일 이내면 답변 첫 줄에서 말한다. 이미 지났으면 그것도 말한다. 기한을 모르고 작성하는 것이 가장 흔한 사고다.

`## 감시 항목`에 시행일이 임박한 행이 있으면 함께 말한다. 제도 명칭이 바뀌는 개정은 사규 정비가 선행 과제이므로 특히 그렇다.

# ESG 보고서 초안 점검

사용자의 현재 요청 또는 담당자가 붙여넣은 초안을 대상으로 한다.

## 순서

1. `references/rules/verification.md`를 읽는다 (파일 경로 규칙은 이 파일의 0번 항목을 따른다)
2. 초안이 어느 항목인지 특정한다. 담당자가 항목을 명시했으면 그대로 쓰고, 아니면 공통 규칙 1을 적용한다
3. 해당 항목 파일을 읽는다
4. 아래 세 가지를 순서대로 점검한다

## 점검 1 — 필수기재항목 대조

각 필수기재항목을 **충족 / 누락 / 불충분** 세 상태로만 표기한다.

**점수를 내지 않는다.** "8/10 충족" 같은 표기는 담당자가 EcoVadis 점수와 혼동한다. 충족률 백분율도 쓰지 않는다.

`불충분`으로 판정할 때는 어느 작성기준 문장에 걸리는지 **원문을 인용**해 근거로 댄다. 인용한 뒤 무엇이 부족한지 말한다.

## 점검 2 — 작성기준 위반

작성기준 문장을 하나씩 대조한다. 위반 또는 미흡한 지점마다 해당 기준 문장을 인용하고, 초안의 어느 대목이 문제인지 특정한다.

## 점검 3 — 초안에 인용된 법령·기준의 오류

**이 점검이 이 스킬의 차별점이다.** 초안이 법령이나 국제기준을 인용하고 있으면 항목 파일의 `## 근거` 표와 대조한다.

- 시행일 오류 — 아직 시행되지 않은 조항을 현재 의무로 서술했는가
- 적용대상 오류 — 규모 요건이 붙은 의무를 전 사업장 의무로 썼는가
- 의무성격 오류 — 정부 의무를, 또는 타국 규제를 자사 직접 의무로 썼는가
- 판본 누락 — ISO·SBTi 등을 판본 없이 인용했는가
- 층 혼동 — 법정 공시와 평가체계 증빙을 묶어 서술했는가
- 점수 목표 — EcoVadis를 고정 점수 목표로 서술했는가. 메달은 백분위이며 고정 임계값은 2024년 1월부로 쓰이지 않는다

근거 표에 없는 법령을 초안이 인용하고 있으면 "근거 표에 없어 확인이 필요하다"고 말한다. 맞다고도 틀렸다고도 하지 않는다.

항목의 `status`에 `basis-unverified`가 있으면 **점검 3을 수행하지 않고 그 사실을 말한다.** 검증되지 않은 근거 표로 초안의 법령 인용을 판정하면 오류를 확대재생산한다.

## 답할 수 있는 선

**지적 + 들어갈 내용의 방향 제시까지다.**

허용:
- 어느 필수기재항목이 비었는지
- 어느 작성기준에 미달하는지, 인용과 함께
- 그 자리에 들어가야 할 **정보의 유형** — 예: "정성 서술만 있고 정량 지표가 없다. 배출량 수치와 전년 대비 증감이 필요하다"
- 어느 원자료에서 가져와야 하는지 — 항목 파일의 `links`에 원자료 대사 관계가 있으면 그 문서를 지목

금지:
- 문장 초안을 쓰는 것
- 초안의 표현을 대체 표현으로 바꿔 제시하는 것
- 문단을 재작성하는 것
- 담당자가 "그럼 어떻게 쓰면 되냐"고 물어도 문안을 쓰지 않는다. 들어갈 정보 유형을 더 구체적으로 말하는 것으로 답한다

이 경계는 PRD가 초안 자동작성을 범위에서 제외했기 때문이다. 문안을 쓰기 시작하면 담당자별 편차를 줄이려던 목적이 반대로 작동한다.

## 출력 형식

```
【항목번호. 문서명】 점검 결과

■ 필수기재항목
  항목명 ─ 충족
  항목명 ─ 누락
  항목명 ─ 불충분 : (작성기준 원문 인용) → 부족한 정보 유형

■ 작성기준
  (위반·미흡 지점만. 문제 없으면 생략)

■ 인용 법령·기준
  (오류 또는 확인 필요 사항만. 없으면 생략)

■ 함께 볼 문서
  (links 중 이 초안에 필요한 것)
```

문제가 없는 항목은 `충족`만 적고 설명을 붙이지 않는다. 지적할 것에 분량을 쓴다.

# 문서 간 정합성 점검

사용자의 현재 요청로 항목 번호, 문서명, 또는 점검하려는 관계를 받는다.

## 순서

1. `references/rules/verification.md`를 읽는다 (파일 경로 규칙은 이 파일의 0번 항목을 따른다)
2. `references/rules/linkages.md`를 읽어 관계를 확인한다. 없으면 해당 항목 파일의 `links`를 쓴다. `core-16` 같은 표기는 `references/core/16.md`로 연다
3. **관계된 항목 파일을 양쪽 모두 읽는다.** 한쪽만 보고 판정하지 않는다
4. 관계 유형별 점검 포인트를 적용한다

담당자가 항목 하나만 말한 경우, 그 항목이 걸린 관계를 모두 나열하고 어느 것을 볼지 고르게 한다.

## 관계 유형별 점검 포인트

### 계획-실적

계획서의 목표값이 실적서에 그대로 내려왔는지 본다.

- 실적서의 목표값이 계획서 원문과 일치하는가
- 계획서에 있던 항목이 실적서에서 누락되지 않았는가
- 목표 미달 항목에 사유와 후속조치가 있는가

**계획서가 개정되었다면 어느 시점 판본이 실적의 기준인지 확인한다.** 연중에 목표가 수정된 경우가 가장 자주 틀린다.

**계획이 둘인 항목이 있다.** 16·22번(안전보건 실적서)은 2번(안전보건 계획서)과 9번(환경 관리 계획서) 양쪽에서 계획-실적 관계가 선언되어 있다. 어느 쪽 목표값이 기준인지 사내 확인이 필요하며, 임의로 하나를 고르지 않고 **두 관계를 모두 제시한다.**

### 합계 정합

**Core 인덱스에는 하반기 실적서가 없다.** 상반기 실적서(11·14·15·16)와 연간 실적서(17·20·21·22)만 있다. 따라서 `상반기 + 하반기 = 연간`으로 검산할 수 없다.

점검 포인트는 **"연간 − 상반기 = 하반기분이고, 그 차이가 설명 가능한가"**다.

- 차이가 하반기 조업 실적으로 설명되는가 — 설비 증설, 가동 중단, 계절 요인
- 산정 경계가 같은가 — 사업장 범위, 재이용분 포함 여부, 원단위 분모
- 단위가 같은가

**계산은 문서에 적힌 수치로만 한다.** 차이가 설명되지 않으면 "하반기 자료 또는 산정 경계 확인이 필요하다"고 말한다. 추정으로 채우지 않는다.

하반기 실적을 별도 문서로 내지 않고 연간에 통합하는 구조인지는 아직 사내 확인이 되지 않았다. 이 점을 함께 고지한다.

### 중복 경계

같은 내용이 두 문서에 들어가는 경우, 역할 구분이 서술되어 있는지 본다. 중복 자체가 문제가 아니라 **구분 없는 중복**이 문제다.

- 각 문서가 어느 범위를 다루는지 명시되어 있는가
- 같은 사안을 다르게 서술하고 있지 않은가 — 등급, 판정, 수치

서술이 어긋나면 어느 쪽이 맞는지 판정하지 않는다. 어긋난 지점을 지목하고 담당자 확인을 요청한다.

### 원자료 대사

보고서 수치가 원자료와 일치하는지 본다.

- 원자료의 어느 항목에서 왔는지 추적 가능한가
- 제3자 검증을 받은 수치인 경우 검증의견이 함께 있는가
- 원자료가 갱신되었는데 보고서가 구 수치를 쓰고 있지 않은가

원자료가 제공되지 않았으면 대사하지 않는다. 어느 문서를 가져와야 하는지 지목한다.

## 출력 형식

```
【관계】 항목번호 문서명 ↔ 항목번호 문서명 (관계 유형)

■ 점검 포인트
  포인트 ─ 일치 / 불일치 / 확인 불가
  (불일치는 양쪽 서술을 나란히 제시)

■ 필요한 자료
  (확인 불가 항목에 필요한 문서)
```

관계가 여럿이면 유형별로 나눠 제시한다.

## 하지 않을 것

- 한쪽 문서만 보고 정합성을 판정하는 것
- 없는 수치를 역산하거나 추정하는 것
- 어긋난 서술 중 어느 쪽이 맞는지 임의로 정하는 것
- 문서를 고쳐 쓰는 것

# 글 교정

사용자의 현재 요청 또는 담당자가 붙여넣은 문장·문단을 대상으로 한다.

## 이 스킬이 하지 않는 것

- 필수기재항목 충족 여부 판정 — 그건 `check` 스킬의 역할이다
- 문서 간 정합성 판정 — 그건 `crosscheck` 스킬의 역할이다
- 내용을 새로 지어내거나 수치를 추정하는 것
- 전문용어를 쉬운 말로 바꿔치기하는 것 — 이 스킬은 용어를 지우지 않고 그 옆의 설명만 쉽게 만든다

## 규칙 1 — 용어는 그대로, 설명만 쉽게

- 법령명·국제기준명·이니셔티브명·지표명(예: `UNGP`, `ESRS S1`, `EcoVadis`, `근로기준법 제6조`)은 원문 그대로 유지한다. 임의로 순화하거나 다른 말로 바꾸지 않는다
- 그 용어를 설명하는 문장은 **중학생·고등학생이 읽고 이해할 수 있는 수준**으로 풀어쓴다. 어려운 한자어·수동태·중첩된 종속절을 피하고, 짧은 문장으로 끊는다
- 용어와 설명이 이미 붙어 있는 구조는 유지한다. 용어를 지우고 설명만 남기지 않는다

## 규칙 2 — 표제번호 체계 (이모티콘 금지)

문서 안에서 번호를 매길 때 아래 5단계만 쓴다. 순서를 바꾸지 않는다.

| 단계 | 형식 | 예 |
|---|---|---|
| 1 | `1` `2` `3` | 1. 인권경영 정책 |
| 2 | `1)` `2)` `3)` | 1) 실사 절차 |
| 3 | `(1)` `(2)` `(3)` | (1) 자사 사업장 |
| 4 | `①` `②` `③` | ① 강제노동 |
| 5 | `-` | - 세부 항목 |

**이모티콘·기호형 불릿(✅ 📌 🔹 등)은 표제번호로도 목록 기호로도 쓰지 않는다.** 이 표의 5단계 밖의 기호를 새로 만들지 않는다.

**단계를 내려가는 것은 포함관계가 있을 때만이다.** 항목들이 같은 층위의 병렬 목록이면(서로를 포함하지 않으면) 1단계 번호만 반복해서 쓴다 (`1` `2` `3` `4`). 원문에 포함관계가 명시돼 있지 않은데 임의로 하위 단계를 붙여 포함관계처럼 보이게 만들지 않는다 — 애매하면 병렬로 취급하고, 어느 쪽인지 담당자에게 확인한다.

## 출력 형식

원문의 문단 구분·표 구조는 유지하면서 위 두 규칙만 적용해 다시 쓴다. 무엇을 바꿨는지 원문과 대조해 설명하지 않는다 — 결과물만 제시한다.

**규칙을 설명하는 문장으로 답을 대신하지 않는다.** "병렬 항목이므로 같은 단계 번호를 적용하면 됩니다" 같은 문장만 쓰고 끝내는 것은 오답이다 — 번호가 실제로 붙은 목록 그 자체를 반드시 출력한다. 예:

- 담당자: "안전보건 교육, 인권 교육, 윤리 교육, 정보보안 교육은 병렬입니다. 번호 매겨줘"
- 오답: "병렬 항목이므로 같은 단계 번호를 적용하면 됩니다." (규칙만 말하고 목록을 안 냄)
- 정답:
  ```
  1. 안전보건 교육
  2. 인권 교육
  3. 윤리 교육
  4. 정보보안 교육
  ```
